### 1.2. Client-project workflows

   - **Context:** A prospecting workflow: find a business without a website and deliver a draft site to them.
   - **Suggested actions:**
     - Search Google Maps for a business in your area that has no website.
     - Screenshot all of the business's photos on Google Maps; that is the only input needed.
     - Paste the screenshots into the AI builder and run `/plan` to generate a PRD (a document describing how to build the site).
     - Copy a prompt from a UI component library so the result looks professional rather than generic.

     - Publish the site and send it to the prospective client.

## 2. Visual design and UI style

### 2.1. Prompt with named UI styles and elements

6. **Name a specific UI style in your prompt** ([2026-07-04](https://www.instagram.com/ivanvibecodes/reel/DaYsHN9iZoO/), [2026-07-07](https://www.instagram.com/ivanvibecodes/reel/DaglDq3lTW-/), [2026-08-02](https://www.instagram.com/ivanvibecodes/reel/Dbha7iDDdIK/), [2026-08-22](https://www.instagram.com/ivanvibecodes/reel/DcWUCIJlKOz/), [2026-08-24](https://www.instagram.com/ivanvibecodes/reel/DccCuGZAO5Y/), [2026-08-25](https://www.instagram.com/ivanvibecodes/reel/DceL6w1j-bP/), [2026-08-26](https://www.instagram.com/ivanvibecodes/reel/DchDbjXDyj_/), [2026-08-28](https://www.instagram.com/ivanvibecodes/reel/DcmZNfZkt_p/), [2026-08-29](https://www.instagram.com/ivanvibecodes/reel/Dco0WOTjBs1/), [2026-09-01](https://www.instagram.com/ivanvibecodes/reel/Dcw1uuuCpQ6/))
   - **Context:** Using the name of a UI style as a keyword gets "results of unmatched quality" from AI builders. Save the video so you remember to try it.
   - **Suggested actions:** use one of these keywords, with the description, in your prompt:
     - **Glassmorphism:** semi-transparent glass-effect elements, blur, frosted surfaces, gradient backgrounds.
     - **Neumorphism:** components that seem to rise from or sink into the surface through soft shadows and subtle contrast.
     - **Claymorphism:** rounded shapes, 3D volume, soft colors, pronounced shadows.
     - **Minimalism:** whitespace, few elements, a clean interface where every detail has a purpose.
     - **Maximalism.**
     - **Brutalism:** deliberately raw, unrefined design; large type, strong colors, unconventional layouts.
     - **Liquid glass.**
     - **Bento grid:** content organized in cards of different sizes inside a modular grid.
     - **Spatial UI.**
     - **Skeuomorphism:** imitates real-world physical objects so digital elements feel familiar.
     - **Aurora UI:** diffuse, glowing gradients reminiscent of the northern lights, usually on dark backgrounds.
     - **Liquid UI:** organic shapes, blobs, fluid gradients and motion that make the interface feel alive.
     - **Bauhaus:** geometric shapes, solid colors, functional composition inspired by modernist design.
     - **Retro:** interfaces inspired by old technology, with vintage type, colors and visuals.
     - **Y2K:** early-2000s look; chrome, transparency, bright colors, futuristic shapes.
     - **Pixel:** inspired by video games and old graphics; visible pixels, retro icons, pixel fonts.
     - **Editorial:** magazine-inspired; large headlines, typographic compositions, hero images, sophisticated grids.

### 2.2. Avoid the "made by AI" look

8. **Remove the visual clichés that give away an AI-generated site** ([2026-09-02](https://www.instagram.com/ivanvibecodes/reel/DcyyRqwFWQ7/), [2026-09-06](https://www.instagram.com/ivanvibecodes/reel/Dc9FdQKFAsp/))
   - **Context:** A checklist of traits that make a site look like it was built by AI.
   - **Suggested actions:** avoid or rework:
     - Heavy gradients, rainbow colors, gradient text in the main heading.
     - Emojis in headings, and long em dashes everywhere in the copy.
     - Pure white backgrounds, drop shadows, cards with colored borders or a colored stripe on the left.
     - Three feature cards (or icon boxes) in a row, a badge above the headline.
     - Lucide icons everywhere, shadcn/ui left unstyled.
     - Inter everywhere, or the Space Grotesk + Instrument Serif pairing, italic serif accents.
     - Glassmorphism cards, the liquid-glass effect, bento grids, terminal-window mockups.
     - Low-contrast dark mode, inconsistent spacing.
     - Fade-in on every scroll, a light beam following the cursor, buttons that fade on hover.
     - Fake testimonials, and generic buzzword copy including "it's not X, it's Y" phrasing.

9. **Replace common AI design defaults with deliberate choices** ([2026-09-08](https://www.instagram.com/ivanvibecodes/reel/DdCZk7WALOq/))
   - **Context:** "Don't do X; do Y instead."
   - **Suggested actions:**
     - Instead of purple-to-blue gradients, use one solid primary color and a curated palette.
     - Instead of gradient text in the main heading, use a strong text color and build hierarchy with size and weight.
     - Instead of emojis in every heading, use icons only where they add information or context.

10. **Fix design problems that make a site look careless** ([2026-09-22](https://www.instagram.com/ivanvibecodes/reel/DdmcsxXiUnW/), [2026-09-22](https://www.instagram.com/ivanvibecodes/reel/DdmSLPEjiPB/))
    - **Context:** Two lists of design mistakes to remove.
    - **Suggested actions:** remove or fix:
      - Overly artificial copy, and lorem ipsum disguised as real content.
      - Excessive shadows, border radius on everything, colors with no system, random gradients, too much glassmorphism.
      - An overloaded navbar, CTAs everywhere, purposeless or unnecessary animations.
      - Typography with no hierarchy, everything centered, giant buttons.
      - Too much empty space, inconsistent icons, cards for absolutely everything.

> **Contradiction to note:** section 2.1 recommends glassmorphism, liquid glass and bento grid as quality keywords, while entries 8 and 10 list the same styles as AI clichés to avoid. The later reels (September) lean towards "avoid".

## 4. Security

### 4.1. Secrets and credentials

16. **Keep secrets out of the client and out of Git** ([2026-08-24](https://www.instagram.com/ivanvibecodes/reel/DcbvQGmiXoW/), [2026-08-29](https://www.instagram.com/ivanvibecodes/reel/Dco7Nl7DzgD/), [2026-09-02](https://www.instagram.com/ivanvibecodes/reel/DcxCOCPj3SX/), [2026-08-27](https://www.instagram.com/ivanvibecodes/reel/Dcj6f1UFSiB/))
    - **Context:** The opening items of the creator's recurring security checklist for AI-built apps.
    - **Suggested actions:**
      - Hide API keys; never publish API keys or secrets in the frontend.
      - Remove secrets from Git history.
      - Use the database's public (anon) key correctly on the client.

### 4.2. Authentication, sessions and accounts

17. **Harden authentication and sessions** ([2026-08-24](https://www.instagram.com/ivanvibecodes/reel/DcbvQGmiXoW/), [2026-08-29](https://www.instagram.com/ivanvibecodes/reel/Dco7Nl7DzgD/), [2026-09-02](https://www.instagram.com/ivanvibecodes/reel/DcxCOCPj3SX/), [2026-09-06](https://www.instagram.com/ivanvibecodes/reel/Dc9P_T2ivdu/), [2026-09-10](https://www.instagram.com/ivanvibecodes/reel/DdHwEeiCiz-/), [2026-09-15](https://www.instagram.com/ivanvibecodes/reel/DdUQnI9j7AH/))
    - **Context:** Authentication items across the security checklists.
    - **Suggested actions:**
      - Enforce authentication on the server.
      - Hash passwords.
      - Protect session cookies with secure flags: HttpOnly and SameSite.
      - Rotate sessions, and reset sessions when the password changes.
      - Limit login attempts and lock accounts after repeated failures.
      - Make password-recovery links expire, and limit password-recovery attempts.
      - Prevent user enumeration.
      - Add bot protection.

### 4.3. Data access and the database

18. **Restrict what each user can read and change** ([2026-08-24](https://www.instagram.com/ivanvibecodes/reel/DcbvQGmiXoW/), [2026-08-29](https://www.instagram.com/ivanvibecodes/reel/Dco7Nl7DzgD/), [2026-09-02](https://www.instagram.com/ivanvibecodes/reel/DcxCOCPj3SX/), [2026-08-26](https://www.instagram.com/ivanvibecodes/reel/Dcg3LAgjHEr/))
    - **Context:** Database items from the checklists and from a list of common vulnerabilities in AI-built apps.
    - **Suggested actions:**
      - Enable row-level security (RLS).
      - Restrict access to records, and block manipulation of sensitive fields (mass assignment).
      - Encrypt sensitive data.
      - Avoid excessive database permissions, and isolate data properly between customers (tenants).
      - Keep backups and a tested restore process.

### 4.4. Input handling and injection

19. **Validate input and escape output** ([2026-08-24](https://www.instagram.com/ivanvibecodes/reel/DcbvQGmiXoW/), [2026-08-29](https://www.instagram.com/ivanvibecodes/reel/Dco7Nl7DzgD/), [2026-09-02](https://www.instagram.com/ivanvibecodes/reel/DcxCOCPj3SX/), [2026-09-06](https://www.instagram.com/ivanvibecodes/reel/Dc9P_T2ivdu/), [2026-09-10](https://www.instagram.com/ivanvibecodes/reel/DdHwEeiCiz-/), [2026-08-26](https://www.instagram.com/ivanvibecodes/reel/Dcg3LAgjHEr/))
    - **Context:** Injection and input items across the security reels.
    - **Suggested actions:**
      - Validate all user input, and sanitize data (and HTML) before storing it.
      - Escape user-supplied content to prevent XSS.
      - Parameterize database queries to prevent SQL injection.
      - Guard against command injection and insecure deserialization.
      - Restrict file uploads with a whitelist of file types, and restrict access to uploaded files.
      - Limit request size.
      - Disable directory listing and remove default admin routes.

### 4.5. Transport, headers and cookies

20. **Configure HTTPS and security headers** ([2026-08-24](https://www.instagram.com/ivanvibecodes/reel/DcbvQGmiXoW/), [2026-09-06](https://www.instagram.com/ivanvibecodes/reel/Dc9P_T2ivdu/), [2026-09-10](https://www.instagram.com/ivanvibecodes/reel/DdHwEeiCiz-/), [2026-09-15](https://www.instagram.com/ivanvibecodes/reel/DdUQnI9j7AH/), [2026-09-15](https://www.instagram.com/ivanvibecodes/reel/DdUbN0PjLDs/))
    - **Context:** Browser-side hardening items.
    - **Suggested actions:**
      - Force HTTPS and add HSTS.
      - Add security headers: a strict Content Security Policy (with violation reporting), X-Content-Type-Options to block MIME sniffing, and a Permissions Policy.
      - Add CSRF tokens.
      - Use Subresource Integrity for third-party scripts.
      - Restrict CORS and validate request origin.
      - Set secure cookie flags.

## 5. Launch readiness
